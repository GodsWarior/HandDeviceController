# Анализ и выбор лицензии / License Analysis & Selection

Документ описывает подбор, сравнение и обоснование выбора лицензии для проекта
**HandDeviceController** (управление курсором мыши жестами руки).

Источники, использованные при подборе:
- **SPDX License List** — официальный каталог идентификаторов открытых лицензий
  (https://spdx.org/licenses/). Каждой лицензии соответствует канонический
  SPDX-идентификатор, который используется в метаданных пакетов и в поле
  `license` файлов `package.json`, `pyproject.toml`, заголовках исходников и т.д.
- **Choose a License** (https://choosealicense.com/) — официальный гид GitHub,
  помогающий сопоставить цели проекта с юридическими условиями лицензий.

## 1. Что за проект и каковы его цели

| Характеристика | Значение |
|---|---|
| Тип | Прикладная десктопная программа (компьютерное зрение + управление вводом) |
| Язык | Python 3.11 |
| Ключевые зависимости | MediaPipe, OpenCV (`opencv-python`), PyAutoGUI |
| Назначение | Управление курсором и кликами жестами руки через веб-камеру |
| Аудитория | Пользователи, разработчики, студенты; потенциально — другие проекты, которые захотят переиспользовать модуль `hand_controller.py` |
| Цель автора | Свободное распространение, возможность использования и доработки сообществом, простая интеграция в другие проекты, отсутствие юридической неопределённости |

Из целей вытекают критерии выбора лицензии:
1. **Разрешительность** (permissive): разрешать использование, изменение, распространение,
   в том числе в закрытых/коммерческих продуктах.
2. **Простота и понятность** для рядового пользователя и разработчика.
3. **Совместимость** с лицензиями зависимостей (важно, т.к. проект связывает
   несколько сторонних библиотек).
4. **Минимум юридических обязательств** для тех, кто просто хочет запустить программу.
5. **Широкая узнаваемость** — лицензия должна быть понятна без чтения полного текста.

## 2. Рассмотренные лицензии (минимум 3)

Ниже — три зрелые, широко используемые лицензии из списка SPDX, покрывающие
разные философии лицензирования: максимально разрешительную (MIT),
разрешительную с явной патентной защитой (Apache-2.0) и строго копилефтную (GPL-3.0).

### 2.1. MIT License (`SPDX: MIT`)

- **Тип:** разрешительная (permissive).
- **Суть:** можно делать практически всё — использовать, копировать, изменять,
  распространять, сублицензировать, продавать. Единственное условие — сохранить
  текст лицензии и уведомление об авторских правах.
- **Объём:** ~170 слов, один абзац.
- **Патенты:** явной патентной оговорки нет (есть только отказ от гарантий).
- **Совместимость:** максимальная; совместима практически со всем, включая
  проприетарные продукты и GPL-проекты (в направлении MIT → GPL).
- **Популярность:** самая распространённая лицензия на GitHub.
- **SPDX URL:** https://spdx.org/licenses/MIT.html

### 2.2. Apache License 2.0 (`SPDX: Apache-2.0`)

- **Тип:** разрешительная (permissive) с явными патентными условиями.
- **Суть:** разрешает использование, изменение и распространение, включая
  коммерческое. Требует сохранять уведомления, файл `NOTICE` (если он есть),
  указывать изменения в файлах.
- **Объём:** длинная и юридически проработанная (несколько страниц).
- **Патенты:** **явная лицензия на патенты** от всех контрибьюторов + патентный
  «возмездие» (patent retaliation) — защита от патентных претензий.
- **Совместимость:** совместима с GPLv3, но **несовместима с GPLv2**; не совместима
  с рядом копилефт-лицензий. Для проприетарного использования пригодна.
- **Популярность:** очень высокая в корпоративном и инфраструктурном ПО.
- **SPDX URL:** https://spdx.org/licenses/Apache-2.0.html

### 2.3. GNU General Public License v3.0 (`SPDX: GPL-3.0-only`)

- **Тип:** строгий копилефт (strong copyleft).
- **Суть:** использовать, изменять и распространять можно, **но** любая
  производная работа при распространении обязана оставаться под GPL-3.0 и
  предоставлять исходный код.
- **Объём:** самая длинная из трёх, со сложными условиями.
- **Патенты:** содержит патентную оговорку и защиту пользователей.
- **Совместимость:** вирусный копилефт; **нельзя** включать в проприетарные
  продукты. Несовместима с Apache-2.0 в одном направлении и т.п.
- **Популярность:** высокая для «идеологического» свободного ПО.
- **SPDX URL:** https://spdx.org/licenses/GPL-3.0-only.html

## 4. Выбор лицензии и обоснование

### Выбрана: **MIT License (`SPDX: MIT`)**

**Почему именно MIT для этого проекта:**

1. **Соответствие цели проекта.** Проект — небольшая прикладная утилита,
   учебно-демонстрационного характера. Автор заинтересован в максимально широком
   и простом распространении, а не в защите от коммерческого использования.
   MIT это обеспечивает полностью.

2. **Простота и понятность.** MIT — одна из самых коротких и однозначных лицензий.
   Пользователю понятно: «делай что хочешь, только сохрани упоминание автора».
   Это снижает барьер входа и юридическую неопределённость.

3. **Нет конфликтов с зависимостями.** Проект связывает MediaPipe, OpenCV и
   PyAutoGUI. MIT-лицензия максимально совместима и не накладывает ограничений,
   которые могли бы противоречить условиям зависимостей.

4. **Широкая экосистемная совместимость.** MIT-код (модуль `hand_controller.py`)
   можно встраивать в другие проекты любой лицензии — это важно, если кто-то
   захочет переиспользовать логику распознавания жестов.

5. **Почему НЕ Apache-2.0.** Apache-2.0 сильнее юридически (патентная защита),
   но и тяжелее: требует файл `NOTICE`, явное указание изменений, длинный текст.
   Для небольшого утилитарного проекта это избыточно и усложняет восприятие.

6. **Почему НЕ GPL-3.0.** GPL-3.0 требовал бы, чтобы все производные работы
   тоже были открыты под GPL. Это противоречит цели — дать возможность
   свободно использовать и встраивать код, в т.ч. в закрытые продукты. Кроме
   того, GPL-3.0 заметно сложнее и создаёт риски случайного нарушения условий.

**Итог:** MIT — оптимальный баланс между свободой использования, простотой
и совместимостью для проекта HandDeviceController.

## 5. Как применена лицензия

- В корне репозитория добавлен файл [`LICENSE`](LICENSE) с полным текстом MIT.
- В начало каждого исходного файла добавлен короткий SPDX-заголовок
  с идентификатором `MIT` и указанием авторских прав
  (рекомендуемая практика SPDX: `SPDX-License-Identifier: MIT`).
- В [`README.md`](README.md) добавлен раздел «Лицензия».
- Лицензия соответствует требованиям
  [GitHub: Adding a license to a repository](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/adding-a-license-to-a-repository).
